系统分为 Gov（政府监管端）和 Ent（企业经营端）两个独立入口，共用同一份 mock 数据源和同一套 Pinia 状态。路由守卫强制隔离——gov 用户无法访问 ent 页面，反之亦然。

getSummary(year) 计算过程:
  输入: summaryData[year] → 4行(城投/产投/水投/领航)
  输出: { rows: 原始4行, total: 汇总行 }

  total 汇总逻辑:
    assets        = Σ 各行 assets          (资产总数)
    bookValue     = Σ 各行 bookValue       (账面原值)
    rented        = Σ 各行 rented          (已出租数)
    idle          = Σ 各行 idle            (闲置数)
    rentalRate    = rented / assets × 100  (出租率, 重新计算)
    idleRate      = idle / assets × 100    (闲置率, 重新计算)
    cumReceivable = Σ 各行 cumReceivable   (累计应收)
    cumActual     = Σ 各行 cumActual       (累计实收)
    yearReceivable= Σ 各行 yearReceivable  (年度应收)
    yearActual    = Σ 各行 yearActual      (年度实收)
    newCert       = Σ 各行 newCert         (新办证数)
    unCert        = Σ 各行 unCert          (未办证数)

5.1 资产统计指标

闲置率闲置数 / 资产总数 × 100Dashboard

5.2 租赁管理统计 (LeaseMgmt stats)

// 从 filteredAssets (经分类+筛选后的资产列表) 计算:
used      = filter(assetStatus === '已使用').length
unused    = filter(assetStatus === '未使用').length
idle      = filter(assetStatus === '闲置')
leased    = filter(leaseStatus !== '未出租').length
idleArea  = idle.reduce(sum, area)
rentRate  = leased / total × 1000 / 10   (保留1位小数)
occupyRate= used / total × 1000 / 10
idleRate  = idle.length / total × 1000 / 10

5.3 合同面积扣减 (leaseSummary)

// 输入一个资产对象，返回其租赁面积情况:
leasedArea    = contracts.filter(c => c.assetId === asset.id)
                         .reduce(sum, c.leaseArea)
availableArea = asset.area - leasedArea
contracts     = contracts.filter(c => c.assetId === asset.id)

跨页面通信

当前系统没有使用事件总线、provide/inject 或共享 composable。唯一的跨页面数据写入发生在 Contract.vue：

  • 意向书转合同时，向 contracts 数组 push 新合同
  • 同时更新 chengtouAssets 中对应资产的租赁状态

由于 ES Module 的导入是活绑定(live binding)，理论上其他引用同一数据的页面能看到变更，但实际上需要刷新页面才会反映。

八、导出功能

所有导出均为客户端 CSV 导出，流程一致：

1. 组装 CSV 字符串 (逗号分隔, 含表头)
2. 添加 UTF-8 BOM (\uFEFF) 确保 Excel 正确识别中文
3. 创建 Blob → URL.createObjectURL → <a download> 触发下载
4. URL.revokeObjectURL 释放内存

涉及页面：资产登记、资产调拨、变更记录、证件信息、电子签章、评估信息、意向书台账、租赁信息、租赁管理、固定资产报表(2个导出函数)。

十、当前系统局限与演进方向

当前状态

本系统为前端原型，所有数据来自 mock.js 或组件内硬编码。主要局限：

  1. 无后端持久化 — 新增/编辑操作仅存于内存，刷新页面即丢失（Contract.vue 的意向书转合同是唯一例外，修改了 mock 模块的活绑定数组）
  2. 工作台 KPI 多为硬编码 — gov 端 6 个 KPI 中 4 个硬编码，ent 端 5 个全部硬编码
  3. 无跨页面实时同步 — 页面间不共享运行时状态，各页面独立加载数据
  4. 图表数据多为静态 — Dashboard 的饼图数据硬编码，仅柱线混合图响应年份切换

向后端演进建议

Phase 1: 引入 API 层
  mock.js → api/assets.js (axios 调用)
  各页面 import 路径不变，仅改数据源

Phase 2: 引入 Pinia 业务 Store
  assetStore   ← chengtouAssets
  leaseStore   ← contracts + leaseData
  warningStore ← warnings + warningTasks
  各页面通过 store 读写，实现跨页面同步

Phase 3: 工作台动态化
  KPI 从 API 获取，不再硬编码
  图表数据从后端聚合接口返回
  预警数据实时推送 (WebSocket)
